# Local fixtures

Audio and transcript files in this directory are intentionally not committed.
P1-B validation used public, non-sensitive Google FLEURS `pt_br` read speech,
revision `70bb2e84b976b7e960aa89f1c648e09c59f894dd`, under CC-BY-4.0. Run
`benchmarks/prepare_fleurs_fixtures.py --help` after obtaining the official TSV
metadata and audio archive to reproduce the 77.68-second quality fixture, the
368.89-second representative fixture and the controlled two-voice fixture.

The generated `.reference.txt` files come from FLEURS human-supervised
transcripts, not model output. The generated manifest records every source file
and SHA-256. The two-voice fixture alternates distinct male/female read-speech
recordings; it is not a natural conversation and has no overlap.

Use exactly the same audio for engine comparisons. The synthetic fixture
generated by the parent script validates only decode, inference and cleanup;
silence/tone cannot support speech-quality or representative-performance claims.

P1-C uses the public AMI `ES2004a` Full-corpus-ASR test meeting. Download the
official headset mix, Array1-01 channel, AMI manual annotation archive v1.6.2,
and clone `https://github.com/pyannote/AMI-diarization-setup`. Then run
`prepare_ami_diarization_fixtures.py` with those four paths. It selects and
records reproducible windows for clean two-speaker speech, controlled unequal
volume, rapid turns, overlap, far-field room audio, and four speakers. Generated
audio, JSONL (`speaker`, `start`, `end`, `text`, `dbfs`) and RTTM files remain
ignored; only aggregate, non-sensitive benchmark results are committed.

Run `benchmark_diarization_robustness.py --help` for DER evaluation. Its primary
score uses a 0.25-second collar and includes overlap; it also stores a secondary
score excluding overlap and compares automatic clustering with
`num_speakers`. Heavy model inference is intentionally outside pytest.

On Docker Desktop/WSL, the benchmark uses total GPU VRAM as a fallback when
`nvidia-smi` does not report per-process memory. JSON records
`vram_measurement=gpu_total`; compare the delta, not the absolute total.
